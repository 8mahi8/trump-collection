# Phase28｜学校iPad向け・人間目線のUI/UXレビュー（2026-10-27）

## 結論

**現時点では学校試遊版にUI/UXの未解決問題があり、技術テスト106/106をそのまま「人間にとって快適な完成版」とは評価できない。** 今回は既にGoogleドライブへ保存した `dist/trump-collection-open-root-trial.html` と同等の単一HTML（Google Docsでのコード全文照合済み）をローカルの Chromium で実画面表示し、**800×450、667×375、1024×768** の3画面サイズで観察した。通信先を触らないため、友達対戦の**試合中レイアウトはローカル注入したダミー状態**で検証（本番Firebaseへは一切書き込んでいない）。学校の実機Safariや本物のGoogle Sitesでは未確認。

## 発見した問題（優先度順）

### P0｜友達対戦の盤面・手札・出すボタンが見えない

- 友達対戦の`online/four-seat-remote.html`は、試合中も「接続・ルーム作成」フォームと「準備・開始」ボタンの**2つの操作パネルが最上部の場所を占有**する。画面の有効高さは外側の「ゲーム一覧」ヘッダーを除いて小さい。
- **800×450の再現（内側iframe 800×398）**では、ダミーの七並べの`documentElement.scrollHeight=549px`。手札は **y=432px以降**、肝心の「選択カードを出す」は**y=488px以降**で、初期表示398pxより外。表示は横幅のみのテストに合格するが、縦方向で大きく欠落する。
- **667×375の再現（内側iframe 667×323）**では、七並べのスクロール高は**601px**、出すボタンは**y=542px以降**。別の画面スクロールを強いる設計では学校で短時間遊ぶ目的に合わない。
- 対処案：試合中はルーム作成フォーム、準備、開始ボタンを収納／非表示（終了・再戦時に適切に表示）、小さい画面では手札＋操作を画面下部へ固定し、残りを盤面に割り当てる。ヘッダー高さや見出しを縮約。**プレイ中にカードと主要操作が同時に見えること**を受け入れ基準とする。

### P1｜COM大富豪のルール設定が小さい画面でスタートできると気づきにくい

- **667×375の再現（内側iframe高さ323px）**では、ルール設定ダイアログでチェック項目しか見えず、`スタート`/`もどる`ボタンは初期表示範囲から完全に消えた（スタートの測定位置 y=338px、内側画面高さ323px）。
- ダイアログは内側スクロール可能だが、初見の友達にはその操作が明示されない。
- 対処案：設定項目部分だけをスクロールさせ、`スタート`/`もどる`をダイアログ下部へ固定。または横2カラムで設定を圧縮。モーダルのスタートは短い画面でも常に見せる。

### P1｜COM七並べの手札・アクション領域が窮屈

- **800×450**の実画面では、13枚程度の手札が大きく重なり、カードの一部分しかタップできないものがある。下端の操作ボタンは画面縁に密着している。
- 選択可能な札の色分け／選択表現は良好。ただし間違えずに目的の1枚を選べる露出幅が狭い。
- 対処案：手札の可視部分と実際のヒットエリアを測定し、密集時は横方向のスワイプや重なり間隔の最小値などを検討。操作ボタンの下部余白を確保。

### P1｜友達対戦がCOM版より「研究用ツール」に見える

- COMはトランプ台・絵札・選択演出がある一方、友達対戦は入力フォームとプレーンなパネル／テキスト表示が中心。選んだゲームに関係なく接続フォームや説明文が幅を取る。
- 「開発版」「研究版」、安全上の注意が繰り返し表示され、ゲーム選択後に**もう一度ゲームセレクタ**が出る。
- 対処案：ルーム作成前はシンプルなホスト／ゲスト選択にする。対戦中は相手人数、手番、場、手札を主役にし、詳細・接続状態は省スペース表示。**現在の公開ルールに関する必要な注意は消さず**、重複しない形に整理する。

### P2｜視認性／細かな操作

- 七並べの4×13盤面表示は情報密度が高く、667px級横画面では数字が小さい。
- COM版の「←ゲーム一覧」と内側の「←メニュー」「最初から」が同時に見え、同じ目的に見えるナビゲーションが重複する。
- 神経衰弱のCOM版は盤面が比較的見やすく、横画面の2段階メニューにも大きな欠けは見られなかった。

## 良かった点

- 初期メニューは4ゲームを1行で選べ、「COMと遊ぶ」「友達と遊ぶ」の二択が明快。
- COMのトランプ表現、手番を示す文言、七並べの合法手ハイライト、神経衰弱の24枚盤面は概ね分かりやすい。
- 既存のChromium/WebKit通信テスト、タッチ`.tap()`、ゲームエンジン完走・復帰テストは実施済み。ただし**タッチできる≠快適に触れる／縦画面に収まる**。

## 修正後の人間目線の受け入れ条件

1. 学校の横iPad想定 800×450 と、さらに低い 667×375 で、**対戦中の手札・アクションが初期表示から見える**。縦スクロールしないと手が打てない状態を残さない。
2. 大富豪の`スタート`/`もどる`が短い横画面でも初期表示内から操作可能。
3. 対戦前に必要な「部屋を作る」「5桁入力」「参加」が押しやすく、対戦開始後は不要なフォームが盤面を占有しない。
4. COMの七並べで出せるカードを指で間違えずに選べる。カード押下領域の実測と必要な改善を実施。
5. UIの改善を行う際も、4画面×3ゲームのFirebaseエミュレータ試験、COM/神経衰弱の回帰、Google Sites単一HTML完全一致ビルドを維持する。
6. **本番Firebase Rules・学校のGoogle Sites公開版は触らない。** 学校iPad実機での最終確認は別途必要。

このレビューは実画面とUIレイアウトの初回レビュー。人間のユーザーテストを実施したという意味ではない。
